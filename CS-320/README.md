CS 320: Software Testing, Automation, and Quality Assurance

This repository contains work from my CS 320 course at Southern New Hampshire University. It includes the Contact and ContactService classes with their JUnit tests from Project One, along with my Summary and Reflections Report from Project Two. These projects helped me better understand how software testing contributes to developing reliable programs and why passing tests doesn't necessarily mean that every problem has been discovered.

How can I ensure that my code, program, or software is functional and secure?

I think one of the most important things is to test software throughout development rather than waiting until everything is finished. In CS 320, I used JUnit to check that my classes followed their requirements and rejected invalid information. I also learned that code coverage alone doesn't guarantee that every problem has been caught. My instructor found weaknesses in my boundary testing even though my tests were passing. Going forward, I would pay more attention to unusual inputs, validation rules, and potential security risks instead of assuming that passing tests mean the software is completely reliable.

How do I interpret user needs and incorporate them into a program?

I start by reviewing the requirements and determining exactly what the program needs to accomplish. For Project One, this meant translating requirements such as character limits, unique IDs, and required fields into code and tests. I think it's important to understand not only what users expect a program to do, but also what should happen when someone enters incorrect information. Clear requirements make it easier to develop software that behaves consistently and meets the user's expectations.

How do I approach designing software?

My approach is to break a larger problem into smaller pieces that are easier to develop and test. In this course, separating the Contact class from ContactService helped me understand the different responsibilities of each component. I could test the validation rules separately from the methods responsible for managing records. I also learned the importance of keeping code organized and making improvements when testing reveals weaknesses. As I continue studying computer science, I want to build on this approach by writing code that is understandable, maintainable, and easier to troubleshoot when something goes wrong.
